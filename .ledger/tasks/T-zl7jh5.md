## Spec

Make exemptions policy-aware: new config key exempt_allowed_paths (list of globs). When set, a commit carrying Ledger-Exempt may only touch files matching those globs (plus .ledger/** always); an exempt commit touching anything else is a coverage error with a fix_hint naming the offending paths. When the key is ABSENT (existing configs), behavior is unchanged (free-text exemptions + exempt-ratio visibility) so upgrading ledger.py never breaks a repo.

init writes a conservative default for new projects: docs/**, *.md, .github/**, .gitignore, .gitattributes, LICENSE*.

Rationale: today 'Ledger-Exempt: misc' on an application-code commit structurally satisfies coverage; 'every implementation change maps to intended work' should be enforceable, not conventional. Subject-pattern exemptions (^Merge, ^Revert) unaffected. Tests: exempt commit touching src-like path fails under policy, passes without the key; docs-only exempt commit passes under policy.


### Enrichment from the external multi-agent review (§19 / §28 item 5, 2026-09-01)

Review §19: an exemption must mean "no product-work obligation exists", never "an obligation exists but task creation is inconvenient"; the rule should be explicit and tested. The spec above is the enforcement half. Confirmed against the code: `classify_commit` exempts any commit carrying a non-empty `Ledger-Exempt:` reason BEFORE inspecting files (both the explicit-trailer branch and the `exempt_patterns` branch short-circuit before `commit_files`); `test_exemption_channels` pins that a commit touching a.txt with `Ledger-Exempt: tooling chore` passes coverage — the loophole is the tested contract; the only counterweight is `exempt-ratio` (info tier, never promoted, no fix_hint). PROTOCOL's "never commit code for work that has no task" exists, but the exemption sentence ("Genuinely unrelated commits use Ledger-Exempt") reads as "unrelated to any existing task". The `coverage` fix_hint never says "create the missing task" (`trailer-dangling`'s hint already says "or add the missing task" — the in-tool precedent). Additions:

- Wording (PROTOCOL_TEXT trailer bullet, at most five lines; regenerate PROTOCOL.md/CLAUDE.md via init; README trailer paragraph; DESIGN §4): "`Ledger-Exempt: <reason>` is ONLY for commits with no product-work obligation: merge/revert mechanics, ledger bookkeeping, generated artifacts (lockfiles, codegen output), docs, CI/repo metadata. Code, test or runtime-behavior changes outside `.ledger/` are never exempt — if no task owns them, `ledger add` one first; 'no task exists yet' is a reason to add a task, not to exempt the commit. The single sanctioned exception is the bootstrap commit `init` prescribes." Add to the Never list: "never edit exempt_allowed_paths / exempt_patterns to make a commit pass — ask via a HUMAN question." Put the exemption taxonomy in the fix_hints, where agents read it at the moment of violation.
- Use a distinct validate code `exempt-policy` (error tier; add to VALIDATION_CODES, the lockstep test and DESIGN §6) instead of reusing `coverage`, so "no trailer" and "exemption abused" are distinguishable. Message names up to three offending paths; fix_hint: "exemptions are only for commits with no product-work obligation; this work needs a task: ledger add ..., then a trailer on the fix; widening exempt_allowed_paths is a project decision — ask via a HUMAN question, do not edit config.json to make this commit pass". Bucket semantics: a violating exempt commit stays in scan's `exempt` bucket (so exempt-ratio and the existing scan test are unchanged) and additionally appears in a new `exempt_policy_violations` list on scan; it is never reclassified as unlinked, so `coverage` and `exempt-policy` never fire together for one commit.
- `coverage` fix_hint gains the ordered remedies: trailer first (amend if unpushed), add-task second, exempt last and bounded; `ledger link` counts as a remedy only if T-5z04ex chooses its option (b) — take the pushed-commit wording from T-5z04ex, which edits the same validate_git loop and the same PROTOCOL_TEXT trailer bullet, and land this fix_hint change after it.
- Generated artifacts (review §19 lists them as a legitimate exemption class): name them in the wording and decide their default globs — lockfiles such as `*.lock`, `package-lock.json`, `poetry.lock` are generic; codegen output directories are project-specific and cannot be known by init's conservative default, so the fix_hint for a generated-artifact commit must point at a HUMAN question to widen `exempt_allowed_paths`, never at filing a task for a machine-produced diff.
- Glob semantics (stdlib): `fnmatch.fnmatchcase(path, glob)`, or `/**` prefix match, or a `/`-less glob matched against the basename (so `*.md`, `.gitignore`, `LICENSE*` match at any depth — say so and test it); always prepend `.ledger/**`; validate that every entry is a non-empty str BEFORE matching and raise LedgerError `config` (exit 2) — `compile_exempt_patterns` only catches re.error, a non-string would raise TypeError. `commit_files` must pass `-c core.quotePath=false` (as the log-tamper pass does) so non-ASCII paths are returned unquoted; today `"docs/\303\244.md"` matches nothing.
- Relationship to DESIGN Appendix 11 (not a reversal): decision 11 rejected path-glob scoping of COVERAGE (which commits need a trailer); this scopes EXEMPTIONS (which commits may claim exempt) and can only make the guarantee stricter — record one sentence in §4 and Appendix 11; add the key to §1's config.json example.
- Do NOT add `exempt_allowed_paths` to DEFAULT_CONFIG (`DEFAULT_CONFIG.update(file)` would enable the policy on every existing repo the moment it re-vendors ledger.py); write it only from `init` when creating config.json. Consequence: the `repo` test fixture runs a fresh `init`, so every repo-fixture test then carries the init default — `test_exemption_channels` must delete the key or use an allowed path (a.txt matches none of the defaults); the hardening evil-merge test gains two extra errors but still passes; the bootstrap flow `init` prescribes (`Ledger-Exempt: ledger bootstrap` including the CI snippet at tests/test_ledger.py) must pass under the default — add `tests/test_ledger.py` to the default globs or change init's hint. This repo's own config.json stays key-absent (or `baseline` moves) because the bootstrap commit b1e2b14 touches tests/ and .ledger/ledger.py.
- Tests: the property test runs on the non-git `plain` fixture with `--no-git`, so the policy is unreachable there — use a `repo`-fixture test asserting `validate --coverage` stays clean after the fixture's own bootstrap under the init default; coverage-error assertions filter by code AND the "has no Ledger-Task/Ledger-Exempt trailer" message (the code is emitted at four sites); pin PROTOCOL.md and the CLAUDE.md block to PROTOCOL_TEXT (currently in sync; guards drift).
- Rejected alternatives (do not reopen): a fixed reason vocabulary for Ledger-Exempt (DESIGN §11 excludes evidence-token vocabularies); promoting `exempt-ratio` to a threshold error (a diagnostic by design); inferring intent ("did behavior change?") — paths are the deterministic proxy (§3: never against agent claims).
- Related: T-jqulvk (one `git diff-tree` per explicit-exempt commit is new cost; include exempt commits in its batching scope), T-2e587s (config schema version).

## Open Questions

- [x] HUMAN: When exempt_allowed_paths is set, should the policy also apply to pattern-exempt MERGE commits (parents > 1) via the --cc combined diff? Verified: `diff-tree --cc --name-only` lists nothing for a clean merge AND for a conflict resolved by taking one side verbatim; it lists only files whose result differs from every parent, so it flags exactly evil-merge content. (a) explicit-trailer channel only (current spec; then DESIGN §4's 'evil-merge content is in scope' sentence must be corrected to 'unless the subject matches exempt_patterns'); (b) also path-check pattern-exempt true merges (single-parent ^Revert and squash merges stay exempt — note the squash gap); (c) path-check every pattern-exempt commit except ^Revert (covers squash merges). Recommendation: (b). -- ANSWERED (2026-09-02): (b) also path-check pattern-exempt TRUE merges via the --cc combined diff. Operator criteria: a clean merge lists nothing (no false positives), an evil merge is real content that must trace to a task; single-parent ^Revert and squash merges stay exempt — record the squash gap in DESIGN as a known limitation and tell agents to put the Ledger-Task trailer in the squash message's last paragraph.
